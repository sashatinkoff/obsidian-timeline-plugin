# Timeline Card — плагин для Obsidian (v2.3)

Карточка-таймлайн (заголовок, дата, опциональный markdown-текст) с инлайн-редактированием, секциями-группами и медиа-сеткой — прямо в Reading View / Live Preview, без сторонних плагинов-помощников.

## Установка

1. Создайте папку `<vault>/.obsidian/plugins/timeline-card/`.
2. Скопируйте туда `manifest.json`, `main.js`, `styles.css`.
3. **Settings → Community plugins** → включите плагин **Timeline Card**.
4. Для наведения-превью (п. 3 ниже) убедитесь, что включён core-плагин **Page preview** (Settings → Core plugins).

## Создание карточки

Быстрее всего — команда **"Вставить Timeline Card"** (Cmd/Ctrl+P → найдите по названию), она вставит пустой шаблон, дальше всё редактируется мышкой.

Либо вручную:

````
```track
## Заголовок карточки (необязательно)

#### День 1

### !Название события
Дата (любой текст)
Текст события — markdown, [[ссылки на заметки]], ![[картинка.png]]

### Ещё событие
Дата

#### День 2

### Событие из второй секции
Дата
```
````

- `## ...` — заголовок карточки (одна строка, необязательно).
- `#### ...` — **секция** (v2.3): заголовок-разделитель, группирующий события ниже него (до следующей секции или конца карточки). Необязательна — можно вообще не использовать.
- `### ...` — обязательно для каждого события. `!` перед названием — событие активное (закрашенный кружок); без `!` — обычное.
- Следующая строка **сразу** после `###` — дата (может быть пустой).
- Всё дальше до следующего `###`/`####` — опциональный markdown-текст.

## Что нового в v2.3

**Секции.**
Кнопка **"+ Добавить секцию"** рядом с «+ Добавить событие» добавляет заголовок-разделитель — клик по названию редактирует его, крестик (при наведении) удаляет. Секция визуально разбивает список: линия таймлайна прерывается на её границе и продолжается заново для событий следующей группы. Секции можно как угодно чередовать с событиями и перемещать, переставляя строки `####`/`###` вручную в источнике заметки.

## Что нового в v2.0–2.2

**1–2. Редактирование и добавление без Source mode.**
Карточка рендерится и в Reading View, и в Live Preview (пока курсор не стоит непосредственно внутри блока — это штатное поведение Obsidian). Клик по заголовку, дате или тексту события превращает их в поле ввода — изменения сразу пишутся в файл. Кнопка **"+ Добавить событие"** дописывает новый пункт, крестик (виден при наведении) — удаляет.
*Ограничение:* это не полноценный WYSIWYG внутри CodeMirror — при клике поле временно становится обычным `input`/`textarea`, поверх карточки. Полная бесшовная интеграция потребовала бы отдельного CodeMirror6-виджета — можно сделать отдельным шагом, если понадобится.

**3. CMD/Ctrl + наведение → превью.**
При наведении на `[[ссылку]]` или `![[вложение]]` с зажатым Cmd (Mac) / Ctrl (Win/Linux) плагин вызывает то же событие `hover-link`, которым пользуется нативный Page Preview — появится стандартное превью заметки или медиафайла. Обычный клик по ссылке (без модификатора) открывает её как всегда.

**4. Автокомплит `[[`.**
При редактировании текста события ввод `[[` открывает список подходящих файлов vault (заметки и медиа, сортировка по совпадению). Стрелки/Enter — выбор, Esc — закрыть. Заметка вставляется как `[[Имя]]`, медиафайл — сразу как встраивание `![[файл.ext]]` (чтобы попасть в медиа-сетку, см. п.5).
*Ограничение:* это собственная реализация (публичного API для вставки в произвольное поле у Obsidian нет), поэтому выпадающий список позиционируется под полем ввода, а не строго под кареткой, как в родном редакторе.

**5. Медиа-сеткой.**
Все `![[картинки]]`, идущие подряд в одном абзаце (без пустой строки между ними), выстраиваются в горизонтальный ряд квадратных блоков (по умолчанию 120×120) с переносом на новую строку, когда заканчивается место. Размер настраивается: **Settings → Timeline Card → Размер медиа-миниатюр**. Под каждой миниатюрой можно показывать подпись (имя файла или alt-текст) — переключатель **Settings → Timeline Card → Показывать описание в карточках медиа** (по умолчанию включено). Изменения этих двух настроек применяются к уже открытым карточкам сразу, без правки заметки.

Начиная с v2.2 картинки (`png/jpg/jpeg/gif/webp/svg/bmp`) плагин рендерит **самостоятельно** — напрямую через `vault.getResourcePath()`, в обход внутреннего механизма эмбедов Obsidian. Именно внутренний механизм в режиме Live Preview иногда не успевал асинхронно подставить картинку и оставлял под ней текст с именем файла как "заглушку" — это не было нашей задуманной подписью, а сбоем самой подгрузки. Теперь картинка либо есть сразу (мы сами формируем `<img>`), либо, если файл не нашёлся, Obsidian покажет её как обычную нерабочую ссылку (без подмены на наш стилизованный блок). Видео/аудио/PDF-эмбеды пока рендерятся как раньше — через сам Obsidian (эта проблема была замечена только на картинках).

*Важно:* в один ряд группируются только эмбеды **внутри одного абзаца** — то есть несколько `![[img.png]]` должны идти на соседних строках без пустой строки между ними.

**Клик по фото — полноэкранный просмотр.**
Клик по миниатюре (без Cmd/Ctrl) открывает изображение на весь экран поверх Obsidian — свой минимальный просмотрщик, не зависящий от Reading/Live Preview. Закрывается кликом мимо картинки или Esc.

**6. Сворачивание длинного текста.**
Если текст события длиннее ~3 строк, он автоматически обрезается с плавным затуханием и появляется ссылка "Показать полностью" / "Свернуть". Ряды с медиа в сворачивание не попадают.

**Автоматическая дата (v2.1).**
При добавлении события через «+ Добавить событие» (или через команду «Вставить Timeline Card») поле даты сразу заполняется текущей датой/временем. Настраивается в **Settings → Timeline Card → Дата события**:
- «Автоматически подставлять дату» — можно выключить, тогда поле останется пустым, как раньше.
- «Формат даты» — нотация moment.js, по умолчанию `YYYY-MM-DD HH:mm` (год-месяц-день часы:минуты).
- «Язык даты» — код локали moment.js (по умолчанию `ru`); влияет на названия месяцев/дней недели, если вы используете их в формате (например `D MMMM YYYY`).

## Известные ограничения

- Редактирование работает через файл: каждое изменение поля сразу сохраняется в заметку и вызывает перерендер блока (это нормально и быстро, но при очень частом наборе текста в date/title полях лучше нажимать Enter/уводить фокус, а не редактировать посимвольно с паузами).
- Список подсказок `[[` не отслеживает позицию каретки пиксель-в-пиксель — это упрощённая реализация, а не полноценный редакторский suggester.
- Полноценное "печатание прямо в Live Preview без выхода в форму" потребует написания собственного CM6 ViewPlugin — сообщите, если это критично, сделаю отдельным этапом.
- Группировка медиа в один ряд работает только внутри одного абзаца (см. п.5 выше) — так надёжнее и не зависит от асинхронной подгрузки.
- Прямой рендеринг (v2.2) сейчас касается только картинок; для видео/аудио/PDF используется обычный эмбед Obsidian — если там тоже периодически будет всплывать имя файла вместо содержимого, дайте знать, распространим тот же подход и на них.

# deploy_plugin.py

Скрипт для автоматического массового обновления или установки плагинов в локальных хранилищах Obsidian. Он избавляет от необходимости вручную копировать файлы, самостоятельно находя `manifest.json` в ZIP-архиве и распределяя плагин по всем базам знаний. Отлично вписывается в процессы автоматизации на macOS, корректно обрабатывая архивы и исключая копирование системного мусора вроде `__MACOSX`.

## Описание возможностей

Утилита распаковывает переданный архив во временную директорию, определяет корень плагина и аккуратно заменяет старые версии в целевых папках `.obsidian/plugins/`. Это делает скрипт удобным инструментом при активной разработке собственных кастомных плагинов для Obsidian или при синхронизации рабочих сред между разными устройствами.

## Как использовать

Для работы скрипта требуется установленный интерпретатор Python. Запустите скрипт через терминал, передав путь к архиву.

**Запуск с параметрами по умолчанию**
По умолчанию скрипт ищет ваши базы знаний в стандартной директории `~/Documents/Obsidian`:
```bash
python deploy_plugin.py timeline-card.zip
```

**Указание пользовательского пути**
Если ваши базы знаний лежат в другой директории, укажите путь к ней с помощью флага `-v` (или `--vaults`):
```bash
python deploy_plugin.py my-plugin.zip -v ~/MyVaults
```
